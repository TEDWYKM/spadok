# Спадок

Застосунок історико-культурного туризму. Карта пам'яток → тематичний
маршрут → навігація по днях → контент і оцінка на місці → нагороди
за пройдений шлях.

**Ключова механіка:** опис пам'ятки й право її оцінити відкриваються
лише після підтвердженого прибуття в точку. Це відрізняє продукт від
путівника і захищає рейтинги від накрутки.

**MVP:** Львівська область — 17 точок, 9 маршрутів, 6 тем, 10 нагород.

Продуктова специфікація — [`docs/spec.md`](docs/spec.md).

## Встановити на телефон

### Швидко: PWA

1. Відкрийте на Android у Chrome посилання GitHub Pages цього
   репозиторію (Settings → Pages показує адресу).
2. Меню Chrome → **Додати на головний екран**.
3. Іконка з'явиться серед застосунків. Відкривається на повний екран,
   працює офлайн, просить доступ до місця під час першої подорожі.

### APK

1. Вкладка **Releases** → останній випуск → файл `spadok-*-debug.apk`.
2. Відкрийте завантажений файл на Android і дозвольте встановлення
   з цього джерела.
3. Під час першої подорожі застосунок попросить доступ до місця.

APK підписаний debug-ключем — цього достатньо для встановлення вручну,
але не для Google Play. Для магазину потрібен release-підпис власним
ключем (`android/app/build.gradle`, `signingConfigs`).

## Розробка

```bash
npm install          # залежності Capacitor і Leaflet
npm run vendor       # покласти Leaflet у www/vendor
npm run icons        # перегенерувати іконки зі SVG-джерела
npm run serve        # http://localhost:8080
```

`localhost` обов'язковий: service worker і геолокація не працюють
з `file://`.

### Перевірки

```bash
node scripts/check.mjs   # цілісність даних, манифесту, правил продукту
node scripts/e2e.mjs     # наскрізний тест у Chromium з підміною GPS
```

`check.mjs` серед іншого стежить, щоб не зникли головні правила —
гейт оцінки й відсутність системних діалогів. `e2e.mjs` ставить
браузер у координати Олеського замку й перевіряє, що картка
відкривається сама, а оцінка приймається тільки після цього.
Знімки екрана лягають у `.e2e/`.

### APK локально

Потрібен Android SDK і JDK 21:

```bash
npx cap add android
node scripts/patch-android.mjs
npm run apk
```

## Структура

```
www/                   застосунок, він же вміст PWA і WebView в APK
  index.html
  css/app.css
  js/data.js           17 точок, 9 маршрутів, теми, нагороди
  js/app.js            стан, геолокація, карта, екрани, дії
  sw.js                офлайн: оболонка + плитки карти
  manifest.webmanifest
  icons/
android-res/           іконки запуску Android (копіюються в проєкт)
scripts/               vendor, icons, patch-android, serve, check, e2e
docs/spec.md           продуктова специфікація
legacy/                прототипи v1 і v2, з яких усе почалося
.github/workflows/     APK у Releases, PWA на Pages
```

Папки `android/` і `www/vendor/` немає в git — їх створює збірка.

## Що змінилося порівняно з прототипом

Прототип (`legacy/spadok-mvp-v2.html`) показував продукт, але сім
речей у ньому лишалися намальованими, а не працюючими:

| | Було в прототипі | Стало |
|---|---|---|
| 1 | Зорепад показувався без відвідин, а під ним стояв текст «оцінку можна залишити лише з місця» | Блок оцінки закритий до підтвердженої відвідини; `saveReview` відхиляє спробу обійти це напряму |
| 2 | `window.storage` — API середовища артефактів; поза ним прогрес зникав при перезавантаженні | `localStorage` із відступом у пам'ять, міграція старого формату оцінок |
| 3 | Кнопка «Я на місці» замість геолокації | GPS із радіусом 300 м і автовідкриттям картки; ручне підтвердження лишилося як резерв і позначається окремо |
| 4 | `alert()` і `confirm()` — у WebView Android ненадійні | Внутрішні шторки й тости |
| 5 | Маршрут прокладався через будь-які точки | Точки з непідтвердженим статусом обходяться, користувач бачить чому |
| 6 | Дата перевірки статусу лежала мертвим полем | Застаріла перевірка позначається на точці й на маршруті, стан видно в профілі |
| 7 | «Завантажити для офлайну» лише міняла свій підпис | Service worker кешує оболонку й плитки карти для рамки маршруту, з прогресом |

Дрібніше: не було `<!DOCTYPE html>` і `<head>`; клас `.tag.stop`
згадувався в коді без правила в CSS; оцінки й тексти лежали в одному
об'єкті через ключі `id` та `id:txt`; відстань між зупинками рахувалася
від останньої точки попереднього дня замість бази; у моношрифті
верхнього регістру «З» не відрізнялося від трійки.

## Відомі межі цієї версії

- Дані демонстраційні: 17 точок, координати приблизні, фото й
  реконструкції — заглушки. Реальний контент і є головний ризик
  проєкту (спека, розділ 3).
- Банер тривоги показує демо-стан: офіційне API потребує токена
  за заявкою. Місце під запит — `Alarms.load()` у `www/js/app.js`.
- Прокладання по дорогах іде через демо-сервер OSRM без гарантій.
  Для продакшену — власний інстанс.
- Прогрес живе на пристрої. Реєстрації й синхронізації між
  пристроями немає — свідомо, це в спеці серед «не увійшло».
- 10 нагород із 50 запланованих.
