# Спадок

Застосунок історико-культурного туризму. Карта пам'яток → тематичний
маршрут → навігація по днях → контент і оцінка на місці → нагороди
за пройдений шлях.

**Ключова механіка:** опис пам'ятки й право її оцінити відкриваються
лише після підтвердженого прибуття в точку. Це відрізняє продукт від
путівника і захищає рейтинги від накрутки.

**MVP:** дві області — Львівщина (17 точок, 9 маршрутів) і Київщина
(7 точок, 4 маршрути). 6 тем, 13 нагород. Область обирається за GPS.

Продуктова специфікація — [`docs/spec.md`](docs/spec.md).
План розвитку, ризики й метрики — [`docs/plan.md`](docs/plan.md).

## Встановити на телефон

### Швидко: PWA

1. Відкрийте на Android у Chrome посилання GitHub Pages цього
   репозиторію (Settings → Pages показує адресу).
2. Меню Chrome → **Додати на головний екран**.
3. Іконка з'явиться серед застосунків. Відкривається на повний екран,
   працює офлайн, просить доступ до місця одразу на карті.

### APK

1. Вкладка **Releases** → останній випуск → файл `spadok-*-debug.apk`.
2. Відкрийте завантажений файл на Android і дозвольте встановлення
   з цього джерела.
3. На першому запуску застосунок попросить доступ до місця — головний
   екран відкривається на вашій позиції. Відмова нічого не ламає:
   відстані рахуватимуться від Львова.

APK підписаний debug-ключем — цього достатньо для встановлення вручну,
але не для Google Play. Пакет для магазину (`.aab`) збирається тим самим
процесом, щойно в репозиторії зʼявляться секрети з ключем підпису —
див. «Ключ підпису для Google Play» нижче.

## Розробка

```bash
npm install          # залежності Capacitor і Leaflet
npm run vendor       # покласти Leaflet у www/vendor
npm run icons        # перегенерувати іконки зі SVG-джерела
npm run serve        # http://localhost:8080
```

`localhost` обов'язковий: service worker і геолокація не працюють
з `file://`.

### Перевірки

```bash
node scripts/check.mjs   # цілісність даних, манифесту, правил продукту
node scripts/e2e.mjs     # наскрізний тест у Chromium з підміною GPS
```

`check.mjs` серед іншого стежить, щоб не зникли головні правила —
гейт оцінки, прохідність кожного дня маршруту, захист сюжетних
маршрутів від перестановки, атрибуція карти, відсутність системних
діалогів. `e2e.mjs` підміняє геолокацію в справжньому Chromium:
питає застосунок, куди він веде, ставить браузер у ту точку й
перевіряє, що картка відкривається сама, а оцінка приймається тільки
після цього. Далі стартує подорож із Бродів і звіряє, що порядок дня
перебудувався, а дорожній режим веде. Окремо перевіряє поїздку до однієї
точки: що трек не стає кільцем, що до зачиненої точки спершу питають,
а після згоди таки ведуть, і що в «маршрути пройдено» вона не потрапляє.
І окремо — що в журналі подорожей немає жодних координат: кабінет
памʼятає, де ви були, але не памʼятає, як ви туди їхали.
Знімки екрана лягають у `.e2e/`.

Тест навмисно відмовляється працювати, якщо на порту 9222 уже висить
браузер від попереднього запуску: причепитись до нього означало б
перевіряти чужий `localStorage` і вірити результату.

**`check.mjs` навмисно падає на застарілих даних.** Якщо у якоїсь точки
перевірка статусу давніша за `STATUS_STALE_DAYS` (120 днів), збірка
зупиняється з переліком таких точок. Це не баг: за правилом 2 протухла
точка випадає з рекомендованих і з маршруту, тож випускати реліз із нею
означає везти людину до зачиненого. Лікується не правкою скрипта,
а звіркою доступності й оновленням поля `upd` у `www/js/data.js`.
Проміжний ярус (60–120 днів) друкується як попередження і збірку
не зупиняє.

### Реліз і версії

```bash
npm run release          # 0.4.0 → 0.4.1
npm run release minor    # 0.4.0 → 0.5.0
npm run release 1.0.0    # рівно ця версія
```

Одна команда піднімає версію в `package.json`, `www/sw.js`
і `www/js/data.js` та перезаписує `release.json` — відбиток того,
що випущено.

Це не бюрократія. PWA оновлюється не так, як застосунок із магазину:
файли лежать у кеші на пристрої, і рішення «це вже інша версія»
ухвалює браузер за одним сигналом — байти `sw.js` змінилися. Поки
версія в `sw.js` лишається тією самою, service worker не переустанов-
люється, і людина, яка вже відкривала застосунок, офлайн бачить стару
оболонку. Помилка невидима зсередини: автор щоразу відкриває з диска.
Саме так `VERSION = 'v1'` пролежала сім релізів поспіль.

Тому `check.mjs` звіряє відбиток оболонки з `release.json` і падає,
якщо файли змінилися, а версія — ні:

```
✗ оболонка змінилася, а версія — ні (0.4.0).
    Змінилося: www/js/app.js, www/css/app.css
    Лікується: node scripts/release.mjs
```

`pages.yml` ганяє `check.mjs` перед деплоєм, тож реліз-привид не доїде
до Pages. Порядок роботи: правки → `npm run release` → `npm run check`
→ коміт → `publish.cmd`.

Кеш плиток карти навмисно названий окремо від версії застосунку:
викачану для офлайну область реліз не стирає. Поточна версія написана
внизу кабінету — щоб на «я не бачу змін» була відповідь на екрані.

### APK локально

Потрібен Android SDK і JDK 21:

```bash
npx cap add android
node scripts/patch-android.mjs
npm run apk        # debug APK
npm run aab        # пакет для Play, якщо задані змінні підпису
```

### Ключ підпису для Google Play

Магазин не приймає debug-підпис. Потрібен власний ключ — і зробити
його маєте ви: у ключа є пароль, а паролями я не розпоряджаюсь.

**1. Створити ключ.** `keytool` іде разом із JDK. Одна команда:

```
keytool -genkeypair -v -keystore spadok-upload.jks -alias spadok -keyalg RSA -keysize 4096 -validity 10000 -storetype PKCS12
```

Запитає пароль і кілька полів про власника — можна відповідати
коротко, у магазині вони не показуються. Файл `spadok-upload.jks`
покладіть **поза репозиторієм** (`.gitignore` його й так не пустить)
і зробіть копію в іншому місці.

Про втрату ключа без паніки: у Play діє Play App Signing — Google
тримає справжній ключ підпису застосунку, а ваш є лише ключем
завантаження. Якщо він загубиться, його скидають через підтримку.
Це не катастрофа, але кілька днів очікування, тож копію все одно
зробіть.

**2. Перекласти ключ у текст** — секрети GitHub бінарних файлів
не приймають. У PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("spadok-upload.jks")) | Set-Clipboard
```

**3. Додати чотири секрети** у **Settings → Secrets and variables →
Actions → New repository secret**:

| Секрет | Що покласти |
|---|---|
| `KEYSTORE_BASE64` | те, що зараз у буфері обміну |
| `KEYSTORE_PASSWORD` | пароль сховища |
| `KEY_ALIAS` | `spadok` |
| `KEY_PASSWORD` | пароль ключа (зазвичай той самий) |

Після цього `android.yml` почне збирати ще й `.aab` — він лягає
в артефакти запуску, не в Releases. Поки секретів немає, процес
працює як раніше й робить тільки debug APK, тож нічого не ламається.

## Структура

```

  index.html
  css/app.css
  js/data.js           області, 24 точки, 13 маршрутів з описами, теми,
                       нагороди, пороги, смуга помітності, текст «про проєкт»
  js/app.js            стан, геолокація, карта, екрани, дії
  sw.js                офлайн: оболонка + плитки карти
  manifest.webmanifest
  privacy.html         політика конфіденційності (вимога Google Play)
  icons/
android-res/           іконки запуску Android (копіюються в проєкт)
release.json           яка версія випущена і з яким відбитком оболонки
scripts/               vendor, icons, patch-android, serve, check, e2e,
                       release, version
docs/spec.md           продуктова специфікація
docs/plan.md           етапи розвитку, ризики, метрики, гроші
docs/server.md         проєкт серверної частини: модель, API, рейтинги
server/schema.sql      схема бази: гейт правила 1 як зовнішній ключ
server/test.sql        20 перевірок схеми на справжньому PostgreSQL
docs/play.html         чеклист публікації в Google Play
legacy/                прототипи v1 і v2, з яких усе почалося
.github/workflows/     APK у Releases, PWA на Pages
```

Папки `android/` і `www/vendor/` немає в git — їх створює збірка.

## Публікація на GitHub

Обидва робочі процеси в `.github/workflows/` розраховані на публічний
репозиторій: на безкоштовному плані GitHub Pages віддає сторінку тільки
з публічного, а APK у Releases має бути доступний за посиланням, щоб його
можна було комусь просто надіслати.

З `gh` — одна команда з кореня репозиторію:

```bash
gh repo create spadok --public --source=. --push
```

Без `gh` — через веб: створити порожній публічний репозиторій `spadok`
(без README, без .gitignore, без ліцензії — вони вже тут), тоді:

```bash
git remote add origin https://github.com/<ваш-акаунт>/spadok.git
git push -u origin main
```

Після першого пуша — вкладка **Actions**:

- `pages.yml` вмикає GitHub Pages сам (`enablement: true`), адреса
  з'явиться в **Settings → Pages**;
- `android.yml` кладе `spadok-*-debug.apk` у **Releases**.

Обидва процеси відфільтровані по шляхах, і на найпершому пуші гілки
GitHub інколи не запускає їх сам. Обидва мають `workflow_dispatch`, тож
у такому разі: **Actions → потрібний процес → Run workflow**. Якщо Actions
вимкнені в налаштуваннях — спершу **Settings → Actions → General**.

`pages.yml` перед публікацією ганяє `check.mjs`, тому застарілі статуси
точок зупинять і деплой PWA — так і задумано.

## Що змінилося порівняно з прототипом

Прототип (`legacy/spadok-mvp-v2.html`) показував продукт, але частина
речей у ньому лишалася намальованими, а не працюючими. Рядки 8–9 —
вже не про прототип, а про те, що додалося пізніше:

| | Було в прототипі | Стало |
|---|---|---|
| 1 | Зорепад показувався без відвідин, а під ним стояв текст «оцінку можна залишити лише з місця» | Блок оцінки закритий до підтвердженої відвідини; `saveReview` відхиляє спробу обійти це напряму |
| 2 | `window.storage` — API середовища артефактів; поза ним прогрес зникав при перезавантаженні | `localStorage` із відступом у пам'ять, міграція старого формату оцінок |
| 3 | Кнопка «Я на місці» замість геолокації | GPS із радіусом 300 м і автовідкриттям картки; ручне підтвердження лишилося як резерв і позначається окремо |
| 4 | `alert()` і `confirm()` — у WebView Android ненадійні | Внутрішні шторки й тости |
| 5 | Маршрут прокладався через будь-які точки | Точки з непідтвердженим статусом обходяться, користувач бачить чому |
| 6 | Дата перевірки статусу лежала мертвим полем | Два пороги: після 60 днів точка позначається і йде нижче рекомендованих, після 120 випадає з треку, як закрита. Кабінет попереджає, коли є про що — і мовчить, коли дані свіжі; `check.mjs` не дає випустити реліз із протухлими |
| 7 | «Завантажити для офлайну» лише міняла свій підпис | Service worker кешує оболонку й плитки карти для рамки маршруту, з прогресом |
| 8 | Подорож завжди починалась від Львова, порядок точок був жорстким | Трек прокладається від ваших координат, порядок дня перебудовується під старт — крім сюжетних маршрутів |
| 9 | Карта в подорожі була такою самою, як у списку | Дорожній режим: повний екран, темна підкладка, слідування з адаптивним зумом, курс, перекладання треку при відхиленні |
| 10 | Головний екран був списком, під яким лежала карта-картка | Карта на весь екран, поверх неї нижня шторка з трьома положеннями; місця й маршрути від найближчого до вас |
| 11 | Позначки різнилися формою — ромб, коло, трикутник — і нічого не означали | Кружальця з кольором за типом обʼєкта; палітра перевірена на симуляції дальтонізму по всіх парах; скупчення збираються в одне коло з кількістю і розпадаються з наближенням |
| 12 | Знайти точку можна було тільки прокруткою списку | Пошук за назвою з шапки: живий фільтр списку й позначок, стійкий до різних апострофів |
| 13 | Усе було прив'язане до однієї області | Точка й маршрут належать області; вона обирається за GPS, перемикається руками і звужує списки, легенду, нагороди й лічильники |
| 14 | Покрокові підказки віддавались у Google Maps | Свої маневри з OSRM українською, озвучення з чесним відступом на екран, екран не гасне, схід із маршруту міряється від лінії треку |
| 15 | Точка на карті була безмовним кружальцем | Аватар над позначкою на близькому зумі: силует типу обʼєкта в слоті під справжнє фото, а поруч — ваш вердикт, якщо ви тут були |
| 16 | Версія кешу лишалася `v1` від релізу до релізу, і хто вже відкривав застосунок, бачив стару оболонку | Одна версія на всі файли, `npm run release` піднімає її скрізь, `check.mjs` не випускає змінену оболонку зі старою версією, смуга «є нова версія» чекає, поки та докачається, а число видно в профілі |
| 17 | Поїхати можна було тільки готовим маршрутом: щоб дістатися однієї памʼятки, доводилось обирати подорож із пʼятьма зупинками | «Прокласти маршрут сюди» з картки будь-якої точки. Трек від вашого місця, дорожній режим, прибуття й оцінка — той самий код, що й у подорожі; до непідтвердженої точки — тільки після явної згоди; у «маршрути пройдено» не зараховується |
| 18 | «Мандрівний лист» був екраном статистики; від завершеної подорожі лишались тільки окремі штампи | Кабінет: профіль зі знаком мандрівника й датою «у Спадку з», журнал подорожей, який пишеться сам, і три вкладки замість одного сувою. Координат у журналі немає — тільки «був у цій точці такого дня» |
| 19 | Для стору бракувало всього: debug-підпис, APK замість AAB, targetSdk 34 | Capacitor 8 з targetSdk 36 і перевіркою планки просто в збірці, релізний підпис із секретів репозиторію, AAB поруч із APK, політика конфіденційності на Pages, налаштування з видаленням акаунта |
| 20 | П’ять зірок і намальовані «4.6 · 1240 оцінок» у демо-даних | Вердикт «варте» / «не варте» з обов’язковою причиною на мінусі — голий мінус це і є замовчаний мінус. Вигадані рейтинги прибрані з даних цілком, і `check.mjs` не дає їм повернутися: спільна думка з’явиться тільки разом із сервером |
| 21 | Поверх карти висіла плашка «Повітряна тривога: немає» з демо-даних | Плашки немає. Стан тривоги — робота застосунків сповіщень, і вони роблять її краще; неправдиве «тривоги немає» гірше за мовчання. Натомість там, де вирішують виїжджати, стоїть нагадування, що графік роботи може змінитися через повітряну небезпеку |
| 22 | Побачити всі точки країни одразу було неможливо: застосунок завжди звужувався до однієї області | Режим «Уся Україна» у виборі регіону. Звуження за замовчуванням лишилось — воно розумне, — але перестало бути вʼязницею. Порожні регіони показуються з нулем: видно, де контенту ще немає |

Дрібніше: не було `<!DOCTYPE html>` і `<head>`; клас `.tag.stop`
згадувався в коді без правила в CSS; оцінки й тексти лежали в одному
об'єкті через ключі `id` та `id:txt`; відстань між зупинками рахувалася
від останньої точки попереднього дня замість бази; у моношрифті
верхнього регістру «З» не відрізнялося від трійки.

## Відомі межі цієї версії

- Дані демонстраційні: 24 точки у двох областях, координати приблизні, фото й
  реконструкції — заглушки. Реальний контент і є головний ризик
  проєкту (спека, розділ 3).
- Стану повітряної тривоги в застосунку немає свідомо: це робота
  застосунків сповіщень, і вони роблять її краще (`docs/spec.md`,
  розділ 2). Лишилося нагадування, що графіки роботи плавають.
- Прокладання по дорогах іде через демо-сервер OSRM без гарантій.
  Для продакшену — власний інстанс.
- Кабінет і прогрес живуть на пристрої. Вхід і синхронізації між
  пристроями немає — свідомо (`docs/spec.md`, розділ 6h). Структура
  даних до неї готова: у профілю і в кожної подорожі є власний id.
  Зворотний бік — телефон загубився без резервної копії, і кабінет
  разом із ним.
- Радіус прибуття один на всі точки — 300 м. Для замкового комплексу
  і для малої церкви це різні числа, але яких саме, покаже тільки
  виїзд у поле (`docs/plan.md`, етап 0).
- Дорожній режим працює, поки екран увімкнений і застосунок відкритий.
  Фонова геолокація в PWA обмежена — це межа платформи, а не недогляд
  (`docs/plan.md`, етап 2).
- Покрокових підказок, голосу й трафіку немає свідомо: для них є кнопка
  передачі точки в Google Maps або Waze (`docs/spec.md`, розділ 6a).
- Захисту від підміни геолокації немає: без сервера перевірити логіку
  переміщення нічим.
- Демо-дані самі старіють. Через 60 днів від `upd` точки почнуть
  позначатися застарілими, через 120 — випадуть з маршрутів, а `check.mjs`
  зупинить збірку. Це не поламка, а те саме правило 2, повернуте
  до автора даних.
- 10 нагород із 50 запланованих.
- Помітність місця — **редакційна оцінка**, а не оцінки користувачів:
  спільних оцінок у застосунку немає й не буде до сервера
  (`docs/server.md`). Тому вона показана словом, а не балом.
- Адреси Telegram, Instagram і YouTube ще не заповнені: у `LINKS`
  вони порожні, і на екрані «Про проєкт» канали підписані «ще не
  створено». Щойно канали зʼявляться — заповнити `www/js/data.js`.
- Конкретна частка прибутку на відновлення памʼяток не названа:
  `GIVING` порожній, на екрані стоїть тільки загальна обіцянка.
- «Авто» для день/ніч рахує схід і захід із координат самого пристрою
  й працює офлайн. Порогом узято сам захід, а не сутінки, — після
  заходу ще близько пів години видно.
