# Спадок

Застосунок історико-культурного туризму. Карта пам'яток → тематичний
маршрут → навігація по днях → контент і оцінка на місці → нагороди
за пройдений шлях.

**Ключова механіка:** опис пам'ятки й право її оцінити відкриваються
лише після підтвердженого прибуття в точку. Це відрізняє продукт від
путівника і захищає рейтинги від накрутки.

**MVP:** Львівська область — 17 точок, 9 маршрутів, 6 тем, 10 нагород.

Продуктова специфікація — [`docs/spec.md`](docs/spec.md).
План розвитку, ризики й метрики — [`docs/plan.md`](docs/plan.md).

## Встановити на телефон

### Швидко: PWA

1. Відкрийте на Android у Chrome посилання GitHub Pages цього
   репозиторію (Settings → Pages показує адресу).
2. Меню Chrome → **Додати на головний екран**.
3. Іконка з'явиться серед застосунків. Відкривається на повний екран,
   працює офлайн, просить доступ до місця одразу на карті.

### APK

1. Вкладка **Releases** → останній випуск → файл `spadok-*-debug.apk`.
2. Відкрийте завантажений файл на Android і дозвольте встановлення
   з цього джерела.
3. На першому запуску застосунок попросить доступ до місця — головний
   екран відкривається на вашій позиції. Відмова нічого не ламає:
   відстані рахуватимуться від Львова.

APK підписаний debug-ключем — цього достатньо для встановлення вручну,
але не для Google Play. Для магазину потрібен release-підпис власним
ключем (`android/app/build.gradle`, `signingConfigs`).

## Розробка

```bash
npm install          # залежності Capacitor і Leaflet
npm run vendor       # покласти Leaflet у www/vendor
npm run icons        # перегенерувати іконки зі SVG-джерела
npm run serve        # http://localhost:8080
```

`localhost` обов'язковий: service worker і геолокація не працюють
з `file://`.

### Перевірки

```bash
node scripts/check.mjs   # цілісність даних, манифесту, правил продукту
node scripts/e2e.mjs     # наскрізний тест у Chromium з підміною GPS
```

`check.mjs` серед іншого стежить, щоб не зникли головні правила —
гейт оцінки, прохідність кожного дня маршруту, захист сюжетних
маршрутів від перестановки, атрибуція карти, відсутність системних
діалогів. `e2e.mjs` підміняє геолокацію в справжньому Chromium:
питає застосунок, куди він веде, ставить браузер у ту точку й
перевіряє, що картка відкривається сама, а оцінка приймається тільки
після цього. Далі стартує подорож із Бродів і звіряє, що порядок дня
перебудувався, а дорожній режим веде. Знімки екрана лягають у `.e2e/`.

Тест навмисно відмовляється працювати, якщо на порту 9222 уже висить
браузер від попереднього запуску: причепитись до нього означало б
перевіряти чужий `localStorage` і вірити результату.

**`check.mjs` навмисно падає на застарілих даних.** Якщо у якоїсь точки
перевірка статусу давніша за `STATUS_STALE_DAYS` (120 днів), збірка
зупиняється з переліком таких точок. Це не баг: за правилом 2 протухла
точка випадає з рекомендованих і з маршруту, тож випускати реліз із нею
означає везти людину до зачиненого. Лікується не правкою скрипта,
а звіркою доступності й оновленням поля `upd` у `www/js/data.js`.
Проміжний ярус (60–120 днів) друкується як попередження і збірку
не зупиняє.

### APK локально

Потрібен Android SDK і JDK 21:

```bash
npx cap add android
node scripts/patch-android.mjs
npm run apk
```

## Структура

```
www/                   застосунок, він же вміст PWA і WebView в APK
  index.html
  css/app.css
  js/data.js           17 точок, 9 маршрутів, теми, нагороди, пороги
  js/app.js            стан, геолокація, карта, екрани, дії
  sw.js                офлайн: оболонка + плитки карти
  manifest.webmanifest
  icons/
android-res/           іконки запуску Android (копіюються в проєкт)
scripts/               vendor, icons, patch-android, serve, check, e2e
docs/spec.md           продуктова специфікація
docs/plan.md           етапи розвитку, ризики, метрики, гроші
legacy/                прототипи v1 і v2, з яких усе почалося
.github/workflows/     APK у Releases, PWA на Pages
```

Папки `android/` і `www/vendor/` немає в git — їх створює збірка.

## Публікація на GitHub

Обидва робочі процеси в `.github/workflows/` розраховані на публічний
репозиторій: на безкоштовному плані GitHub Pages віддає сторінку тільки
з публічного, а APK у Releases має бути доступний за посиланням, щоб його
можна було комусь просто надіслати.

З `gh` — одна команда з кореня репозиторію:

```bash
gh repo create spadok --public --source=. --push
```

Без `gh` — через веб: створити порожній публічний репозиторій `spadok`
(без README, без .gitignore, без ліцензії — вони вже тут), тоді:

```bash
git remote add origin https://github.com/<ваш-акаунт>/spadok.git
git push -u origin main
```

Після першого пуша — вкладка **Actions**:

- `pages.yml` вмикає GitHub Pages сам (`enablement: true`), адреса
  з'явиться в **Settings → Pages**;
- `android.yml` кладе `spadok-*-debug.apk` у **Releases**.

Обидва процеси відфільтровані по шляхах, і на найпершому пуші гілки
GitHub інколи не запускає їх сам. Обидва мають `workflow_dispatch`, тож
у такому разі: **Actions → потрібний процес → Run workflow**. Якщо Actions
вимкнені в налаштуваннях — спершу **Settings → Actions → General**.

`pages.yml` перед публікацією ганяє `check.mjs`, тому застарілі статуси
точок зупинять і деплой PWA — так і задумано.

## Що змінилося порівняно з прототипом

Прототип (`legacy/spadok-mvp-v2.html`) показував продукт, але частина
речей у ньому лишалася намальованими, а не працюючими. Рядки 8–9 —
вже не про прототип, а про те, що додалося пізніше:

| | Було в прототипі | Стало |
|---|---|---|
| 1 | Зорепад показувався без відвідин, а під ним стояв текст «оцінку можна залишити лише з місця» | Блок оцінки закритий до підтвердженої відвідини; `saveReview` відхиляє спробу обійти це напряму |
| 2 | `window.storage` — API середовища артефактів; поза ним прогрес зникав при перезавантаженні | `localStorage` із відступом у пам'ять, міграція старого формату оцінок |
| 3 | Кнопка «Я на місці» замість геолокації | GPS із радіусом 300 м і автовідкриттям картки; ручне підтвердження лишилося як резерв і позначається окремо |
| 4 | `alert()` і `confirm()` — у WebView Android ненадійні | Внутрішні шторки й тости |
| 5 | Маршрут прокладався через будь-які точки | Точки з непідтвердженим статусом обходяться, користувач бачить чому |
| 6 | Дата перевірки статусу лежала мертвим полем | Два пороги: після 60 днів точка позначається і йде нижче рекомендованих, після 120 випадає з треку, як закрита. Стан видно в профілі, а `check.mjs` не дає випустити реліз із протухлими даними |
| 7 | «Завантажити для офлайну» лише міняла свій підпис | Service worker кешує оболонку й плитки карти для рамки маршруту, з прогресом |
| 8 | Подорож завжди починалась від Львова, порядок точок був жорстким | Трек прокладається від ваших координат, порядок дня перебудовується під старт — крім сюжетних маршрутів |
| 9 | Карта в подорожі була такою самою, як у списку | Дорожній режим: повний екран, темна підкладка, слідування з адаптивним зумом, курс, перекладання треку при відхиленні |
| 10 | Головний екран був списком, під яким лежала карта-картка | Карта на весь екран, поверх неї нижня шторка з трьома положеннями; місця й маршрути від найближчого до вас |
| 11 | Позначки різнилися формою — ромб, коло, трикутник — і нічого не означали | Кружальця з кольором за типом обʼєкта; палітра перевірена на симуляції дальтонізму по всіх парах; скупчення збираються в одне коло з кількістю і розпадаються з наближенням |

Дрібніше: не було `<!DOCTYPE html>` і `<head>`; клас `.tag.stop`
згадувався в коді без правила в CSS; оцінки й тексти лежали в одному
об'єкті через ключі `id` та `id:txt`; відстань між зупинками рахувалася
від останньої точки попереднього дня замість бази; у моношрифті
верхнього регістру «З» не відрізнялося від трійки.

## Відомі межі цієї версії

- Дані демонстраційні: 17 точок, координати приблизні, фото й
  реконструкції — заглушки. Реальний контент і є головний ризик
  проєкту (спека, розділ 3).
- Банер тривоги показує демо-стан: офіційне API потребує токена
  за заявкою. Місце під запит — `Alarms.load()` у `www/js/app.js`.
- Прокладання по дорогах іде через демо-сервер OSRM без гарантій.
  Для продакшену — власний інстанс.
- Прогрес живе на пристрої. Реєстрації й синхронізації між
  пристроями немає — свідомо, це в спеці серед «не увійшло».
- Радіус прибуття один на всі точки — 300 м. Для замкового комплексу
  і для малої церкви це різні числа, але яких саме, покаже тільки
  виїзд у поле (`docs/plan.md`, етап 0).
- Дорожній режим працює, поки екран увімкнений і застосунок відкритий.
  Фонова геолокація в PWA обмежена — це межа платформи, а не недогляд
  (`docs/plan.md`, етап 2).
- Покрокових підказок, голосу й трафіку немає свідомо: для них є кнопка
  передачі точки в Google Maps або Waze (`docs/spec.md`, розділ 6a).
- Захисту від підміни геолокації немає: без сервера перевірити логіку
  переміщення нічим.
- Демо-дані самі старіють. Через 60 днів від `upd` точки почнуть
  позначатися застарілими, через 120 — випадуть з маршрутів, а `check.mjs`
  зупинить збірку. Це не поламка, а те саме правило 2, повернуте
  до автора даних.
- 10 нагород із 50 запланованих.
